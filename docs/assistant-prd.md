# Desktop Desk 助理化需求清单（v0.1）

> 目标读者：作者本人 + 实现者（DSH）。
> 本文是 v0 草案：先把"为什么鸡肋"拆成可验收的需求，再排里程碑。
> 原则：先改数据可信，再谈助理；先只读，再行动；先 observe，再 auto。

---

## 0. 一句话目标

把板子从**"需要你主动去看的仪表盘"**变成**"只在该说话时说话的个人助理"**：

- 它知道你在推进什么（项目/学习/关注点），以及到了哪一步；
- 它的数字**比打开官网更省事**（完整、多账号、带时间、有历史）；
- 它会在需要你决策时**主动开口**，其余时间保持安静；
- 你能对它说一句话，它**长出一张卡**、排一份今天的计划。

非目标（v1 不做）：通用聊天窗；让 LLM 直接写 C++/编译；多显示器/移动端；替你付款或操作账号；无来源的"洞察"。

---

## 1. 设计原则

参考 DeepSeek Harness 团队的 Super-agent 设计（2026-10-31）：

1. **注意力是预算**：每条通知、每张卡都要证明自己省了时间；健康状态不占空间。
2. **默认 observe**：主动行为先只记录"本来会做什么"，你看过记录再转 auto。
3. **只在三种情况开口**：需要你决策 / 有结果可用 / 干不下去。
4. **没有来源不显示，没有时间不当"当前"**：数字必须带 as-of 与陈旧标记。
5. **确定性代码管权限与状态，LLM 管"非标准 → 结构化"与判断**。
6. **卡片是配置，不是代码**：LLM 产出 CardSpec，运行时解释；不生成可执行代码。
7. **Session 是系统实现细节，不是你的认知负担**：板子只呈现"事"，不呈现"会话"。

## 2. 现状证据（为什么鸡肋）

| 现象 | 证据 |
|---|---|
| 几乎不会主动看 | 无通知通道；托盘只有 NIM_ADD；服务器/额度异常只改颜色 |
| 没有交互 | 入口只有右键菜单/托盘；唯一"对话"是在 PS 卡里调 pi，粗糙 |
| Codex 额度会长时间不变 | 只按 300s 刷新；取 `~/.codex` 最新 rollout 的 rate_limits，不监听文件变化、无 as-of |
| DeepSeek 余额无参考价值 | 差额法（当日余额差）+ 本机口径 + 需基线；用户已不用官方渠道 |
| CommandCode 不准/不全 | 单账号；无月限额；无已用 token；无时间序列；与官网差个位数 |
| 没有历史 | 只有当日快照（`tok.day` 每日清零）；无 7/30 天曲线，无法回答"这周用了多少" |
| 不能"管事" | 无项目/任务/计划模型；无主动监督；无自然语言生成卡片 |

**结论**：当前理性选择就是打开浏览器——板子必须做到"比官网更省事"，否则卡片越多越鸡肋。

## 3. 需求清单

### A. 数据可信层（P0，先做）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| A1 | **多账号**：CommandCode 支持 N 个账号（label + 独立 key），卡片显示聚合行，展开看每账号 | P0 | 自动导入 DSH refs 里的两个 key（`COMMANDCODE_API_KEY`、`..._2`）；label 可改；聚合=两者之和；单账号失败只影响自己那一行 |
| A2 | **月额度**：5h / 周用 API 的 used/cap；月额度显示 `monthlyCredits` 余额，支持可选手动上限 | P0 | 有上限时显示百分比与剩余；没有时显示余额并标"手动上限未设"；重置时间倒计时；`resetAt=0` 显示"无" |
| A3 | **已用 token**：本机 DSH 汇总（Input/Output/Cache read/Cache write），标 `LOCAL` | P0 | 按 provider 能拆则拆；无数据时显示 `--` 不显示 0；与账户余额分开算 |
| A4 | **时间序列**：7/30 天折线或柱状（token、额度使用率、花费） | P0 | 图表可切换 7/30 天；当天数据 5 分钟内可见；历史从启用日开始（更早仅在能归因时近似） |
| A5 | **新鲜度**：每条数据带 as-of；文件变化立即刷新；超时标 `STALE` | P0 | Codex rollout 追加后 ≤10s 更新；>60min 未更新显示 `STALE 1H` 并变灰 |
| A6 | **DeepSeek 行移除**：默认不显示（代码留作 CardSpec 重建的样例） | P0 | 默认隐藏；未来用 CardSpec 一句话恢复，不改 exe |
| A7 | **失败可诊断**：区分 NET / 鉴权 / 接口变更 / 解析失败，并给下一步 | P1 | 401→"更新 Key"；NO DATA→"接口可能变更，查看原文"；每行可展开最近错误 |
| A8 | **口径透明**：每个数字旁可查"来源 / 时间 / 计算方式" | P0 | 点开详情能看到来源文件/接口与计算说明；本地口径永远标 `LOCAL` |
| A9 | **沙箱配额**：CommandCode 的 `sandboxMinutes`（used/limit/overage）也显示 | P1 | 与 5h/周同处展开详情；超限时有提示 |

### B. 助理入口（P0/P1）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| B1 | **呼出热键**：任意前台窗口下召唤助理面板（不要求最小化） | P0 | 按 `Ctrl+Alt+A` ≤300ms 出现；不抢焦点超过 1s；再按隐藏 |
| B2 | **ASK 输入**：板内直接提问 + 流式回答 + 引用来源 | P1 | 键盘可输入、可编辑、可复制；回答带"依据：session/仓库/时间"；无依据时明确说不知道 |
| B3 | **BRIEF 卡**：3–5 行"今天/本周"（项目 + 状态 + 卡点 + 下一步） | P0 | 每次打开 5s 内可读完；每行可展开证据；空状态不占空间 |
| B4 | **通知通道**：托盘气泡 / 角落 toast / 可选声音 | P0 | 通知可点击直达对应卡片；可静音；同一事件不重复 |
| B5 | **健康状态为空** | P0 | 没有需要你处理的事时，BRIEF 只显示一行"没有需要你处理的事" |
| B6 | **前台窗口感知**：知道你在写代码/看视频/浏览，用于判断打扰时机 | P1 | 只读窗口标题/进程名；设置里可关；不截屏（截图另开开关） |

### C. 主动监督（P0/P1，贾维斯的核心）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| C1 | **事件源**：DSH 会话、Git、Codex 文件、账号数据、服务器、计划、日历（可选） | P0 | 每类源有"最后事件时间"；断流时自报（Watchdog 思路） |
| C2 | **触发器**：定时 / 数据变化 / 阈值 / 停滞 N 天 / 失败 / 你回来 | P0 | 服务器 DOWN、额度 ≥90%、项目停滞 7 天、计划任务过期可触发 |
| C3 | **评估两段式**：Fast Path 确定性规则 + Slow Path LLM 语义判断 | P0 | 明确规则不花 token；LLM 只判"要不要开口/怎么说"；默认 observe |
| C4 | **通知预算**：每天 ≤N 条、可静音、可分级 | P0 | 默认每天 ≤3 条；超预算只记录不打扰；周报里可查 |
| C5 | **每日/每周简报**：做了什么、计划完成度、卡点、明日建议 | P1 | 早晚各一次；可手动重生成；来源可展开 |
| C6 | **停滞与偏离**：项目无推进、计划任务超期、额度异常消耗 | P1 | 停滞判定可配置（默认 7 天）；先 observe 一周再 auto |
| C7 | **observe 面板**：列出"本来会做什么"，一键转 auto | P1 | 每条含触发原因/拟动作/影响；转 auto 需确认 |
| C8 | **每天一件最重要的事**：只给一个"今天必须先做"的建议 | P0 | 每天一次；可"换一个/今天不做"；有依据（里程碑/截止/停滞） |

### D. 自然语言生成卡片（P1/P2，差异化能力）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| D1 | **CardSpec DSL**：数据源（http/exec/file/dsh）+ 解析（json/regex/llm_extract）+ 布局（rows/list/bar/line/table）+ 刷新 + 尺寸 | P1 | 手写一份 CardSpec 能在板上渲染；非法 spec 有可读错误 |
| D2 | **对话生成卡片**：说"我要一张 X 卡" → 生成 spec → 预览（observe）→ 确认上板 | P1 | 3 轮对话内产出可用的只读卡；生成失败给具体原因；可回滚 |
| D3 | **卡片库**：保存/复用/编辑/删除；版本化 | P2 | 卡片可导出/导入 JSON；改坏可回滚上一版 |
| D4 | **安全边界**：能力白名单；exec 需确认；凭据只引用不导出 | P0 | 默认只读 HTTP/文件；exec 类卡片必须逐条确认；密钥不出现在 spec/日志 |
| D5 | **LLM 作为适配层**：把网页/日志/截图/JSON 等非标准数据映射成结构化行 | P2 | 输入一份非标准文本，能产出符合 Row 模型的结果；有失败兜底 |
| D6 | **卡片自愈**：数据源失效时标红并给修复建议 | P1 | 失效卡片不显示旧数据当新数据；提示"改 URL/字段/重生成" |

### E. 看板 / 任务 / 计划（P1/P2）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| E1 | **今日计划**：说"帮我安排今天"，生成时间块+优先级；每天自动更新 | P1 | 生成后可手动改；完成后打勾；未完成次日提示 |
| E2 | **任务模型**：待办/进行中/完成/搁置；与项目绑定 | P1 | 任务状态变更 ≤2 次点击；跨天保留 |
| E3 | **项目/里程碑**：每个项目 1–3 条当前目标 + 完成判据 | P0 | 没有里程碑的项目不允许被判"进度"；助理明确"Insufficient evidence" |
| E4 | **学习跟踪**：按主题/章节记录（考公、自动控制原理、神经网络…） | P2 | 可从会话结论里建议章节进度，需你确认 |
| E5 | **周报复盘**：完成/停滞/时间分布，可导出 Markdown | P2 | 每周生成一次；可复制到笔记 |

## 8. CommandCode API 探测结论（2026-11-07）

用本机 DSH 凭据里的两个 key 只读 GET `https://api.commandcode.ai/alpha/billing/credits`（经本机代理 127.0.0.1:7897），两个账号均 200。

**凭据**
- `~/.dsh/.credentials.yaml` 的 refs 里已有两个 key：`COMMANDCODE_API_KEY`、`COMMANDCODE_API_KEY_2`；凭据管理器里**没有** `AiMeter/CommandCode` 条目。
- 当前 `LoadCommandCodeKey()` 只读第一个 → 第二个账号永远不可见（与你的观察一致）。

**响应字段（两账号同构）**

| 字段 | 含义（待确认） | 账号1 | 账号2 |
|---|---|---|---|
| `credits.monthlyCredits` | 月额度余额（疑） | 0.78 | 59.67 |
| `credits.creditThreshold` / `belowThreshold` | 低额度阈值 / 是否低于 | 0 / false | 0 / false |
| `windowLimits.fiveHour.used` / `.cap` | 5h 窗口 | 5.41 / 14 | 0 / 14 |
| `windowLimits.fiveHour.resetAt` | 重置时间 | 11-07 04:48 | 0（无窗口） |
| `windowLimits.weekly.used` / `.cap` | 周窗口 | 25.45 / 35 | 10.33 / 35 |
| `windowLimits.weekly.resetAt` | 重置时间 | 11-12 16:09 | 11-12 02:40 |
| `sandboxMinutes.usedMinutes` / `limitMinutes` / `overageUsd` | 沙箱分钟配额 | 0 / 0 / 0 | 同 |
| `sandboxMinutes.resetAt` | 沙箱周期 | 12-01 08:00 | 12-01 08:00 |

**没有的字段**
- 没有账号身份（id/email/plan）→ 多账号只能靠手动 label 区分；
- 没有 monthly 窗口（used/cap）→"月限额"只能显示余额 + 可选手动上限；
- 没有 token 计数 → 已用 token 只能来自本机 DSH `session_projcache`，标 `LOCAL`，无法按账号拆分；
- `resetAt=0` 表示当前窗口未启用/无记录，UI 显示"无"，不要显示"已重置"。

**可直接用的告警触发器（C2）**
- `fiveHour.exceeded` / `weekly.exceeded` 为 true；
- `belowThreshold` 为 true，或 `monthlyCredits` 低于自设阈值；
- 周窗口重置前 N 小时提示"额度即将重置，剩余 X"。

**探测方法备注**
- DSH 进程沙箱下 Schannel/curl 取不到 TLS 凭据（`SEC_E_NO_CREDENTIALS`），改用捆绑 Python（OpenSSL）+ 显式 HTTP 代理完成只读探测；key 只在内存中使用，未落盘。

## 10. Agent 运行时：pi 评估与结论

**结论：v1 把 pi 当 Worker 引擎嵌入（RPC 模式），不 fork。**

本机 pi 是 `@earendil-works/pi-coding-agent` 1.4.0（MIT，Node ≥22.19），已配 deepseek provider。它已经提供：

- `--mode rpc`：JSONL 长驻子进程（命令 / 响应 / 事件），语言无关，适合 C++ 宿主；
- SDK（Node 进程内）：`createAgentSession()`、`SessionManager`、事件订阅；
- 会话持久化 / 恢复 / 分叉、自动 compaction、`--session-dir`；
- 工具（read/bash/edit/write）、MCP、skills、TypeScript 扩展（jiti 直接加载 `.ts`）；
- `--system-prompt` / `--append-system-prompt`（人格与规则）、`--tools` 白名单；
- 多 provider（本机已配 deepseek，auth 可复用）。

它没有的，正好是我们该做的：

- 没有 scheduler / trigger（"主动"）→ 桌面侧 Trigger/Eval；
- 没有长期记忆（docs 里没有 memory 概念，只有会话与 compaction）→ 桌面侧记忆库 + 夜间巩固；
- 没有"注意力预算 / 通知" → 桌面侧 Channel。

**架构（对应 Super-agent 的 Router/Worker）**

```text
desk.exe (C++)                                 pi child (Node)
├─ Channel: 板 / 卡片 / 通知 / 热键   ⇄ JSONL RPC ⇄  Router session（轻模型：要不要说）
├─ Router: Source → Trigger → Eval                Worker session（强模型：带工具干活）
├─ Memory: episodes / facts / retrieval
└─ Tools: 写卡 / 通知 / 执行（结构化输出或扩展回调）
```

**为什么不是 fork**

- 它迭代快（安装器带 releases / 版本升级），fork 会冻结版本、双份维护；
- 扩展 API（tools / commands / hooks）+ `--system-prompt` 足够覆盖"人格 / 记忆工具 / 板工具"；
- 我们真正需要的"主动"不在它内部，改它核心也解决不了；
- 只有在需要改会话格式 / 循环，或要单二进制时才考虑 fork（v2 以后再评估）。

**两种接法**

- v1（推荐）：desk.exe 直接起 `pi --mode rpc --session-dir <cfg> --tools ... --append-system-prompt <persona.md>`，C++ 实现 JSONL 客户端（约 300 行：命令 / 事件 / 超时 / 重连）。
- v2：Node 桥（pi SDK + 扩展），C++ 通过命名管道或本地 HTTP 调用；记忆 / 板工具用 TS 扩展写，开发更快。

**模型分工**

- Router：deepseek flash 级别（判断要不要开口、说什么）；
- Worker：同 provider 的强模型（做任务 / 整理 / 生成 spec）；
- 预算只看用量，不设人为上限；异常时熔断。

**失败处理**

- pi 子进程崩溃 / 卡死：重启 + 保留会话；RPC 超时 60s；事件落盘可重放；
- 模型 / 网络失败：降级为规则摘要并明确标注。
